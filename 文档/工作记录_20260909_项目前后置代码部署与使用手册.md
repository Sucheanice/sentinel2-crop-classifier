### 2.4 使用方法（命令示例）

耕地识别（farmland 微调权重，最终 fix2 口径）：

```bash

cd /data4/sam3_project/sam3_train/Code/sam3-main/sam3_service
export CUDA_VISIBLE_DEVICES=0,2,3,4,5,6

nohup python geo_infer_v10_multigpu.py \
  --input /data3/sam3_project/test_data/tif/baozhucun.tif \
  --output /data3/sam3_project/test_data/result_baozhucun_v10_fix2/baozhucun_v10_fix2 \

  --gpus 0,2,3,4,5,6 \
  --checkpoint /data4/sam3_project/sam3_train/data/runs/finetune_v3/checkpoints/checkpoint_25.pt \
  --geometric-refine 0 --confidence-threshold 0.3 \
  --dark-p10-threshold 25 --ndvi-threshold 0 \
  --simplify-tolerance 1.0 --mask-smooth-sigma 1.0 \
  --max-vertices 200 \
  --min-area-m2 67 --merge-touching 1 --merge-fill-hole-m2 0.0 \
  --stretch 0 --slic-points 1 \
  > run.log 2>&1 &
```

### 2.5 参数说明与调整（`geo_infer_v10_multigpu.py`）

| 参数 | 默认 | 含义 / 调整建议 |
|---|---|---|
| `--prompt` | farmland | 文本提示词；farmland / water / greenhouse |
| `--gpus` | 0,6 | 逗号分隔 GPU 编号 |
| `--checkpoint` | 必填 | 模型权重路径 |
| `--confidence-threshold` | 0.3 | 实例置信度阈值；默认 0.5 偏高会漏检，降到 0.3~0.4 |
| `--geometric-refine` | 1 | 框几何精修（0=关）；water 时置 0 |
| `--refine-low` / `--refine-high` | 0.23 / 0.60 | 框精修的置信区间 |
| `--slic-points` | 1 | SLIC 超像素点提示（提召回，兜底文本漏检）；water 时置 0 |
| `--slic-segments` / `--slic-compactness` | 64 / 10.0 | SLIC 超像素数量/紧凑度 |
| `--slic-min-brightness` | 70.0 | SLIC 亮度门 |
| `--stretch` | 0 | 直方图拉伸（0=关，保持原始 12bit 值域） |
| `--tile-size` / `--core-size` / `--core-overlap` | 1008 / 672 / 168 | 粗尺度（Context-Core）窗口 |
| `--fine-tile-size` / `--fine-core-size` / `--fine-overlap` | 588 / 448 / 0.25 | 细尺度（Fine-Tile）窗口 |
| `--skip-empty-windows` | 1 | 跳过 nodata/全黑无效窗口 |
| `--dark-p10-threshold` | 25 | 暗色过滤（归一化亮度 p10）；>0 启用；water 时置 0；调大误删耕地 |
| `--ndvi-threshold` | 0 | NDVI 林地过滤（>0 启用；实测 band4 非标准 NIR，勿用） |
| `--simplify-tolerance` | 1.0 | Douglas-Peucker 简化容差；调大会过度简化 |
| `--mask-smooth-sigma` | 1.0 | mask 高斯平滑 sigma |
| `--max-vertices` | 200 | 顶点上限；仅对 >200 顶点的极端多边形做共线点合并 |
| `--fill-holes` / `--hole-area-pixels` | 1 / 268 | 补洞开关 / 洞面积阈值 |
| `--remove-overlap` | 1 | 重叠裁决（分数优先） |
| `--min-area-m2` | 67 | 最小地块面积；water 时可降到 50 |
| `--merge-touching` | 1 | 相接合并 |
| `--merge-fill-hole-m2` | 0.0 | 相接合并后的补洞面积阈值（0=不补） |

### 2.7 潜在问题

1. **模型灾难性遗忘**：`checkpoint_25.pt` 是 farmland 微调，已遗忘 water/greenhouse 语义。做水体必须切回原始 `sam3.pt`；做耕地只能用微调权重。
2. **大棚/greenhouse 不可行**：纯 prompt 召回 1.7%，规则检测最好召回 36%、精确 29%（裸土/红土光谱不可分）。需深度学习，已挂起。
3. **线状水体漏检严重**：沟渠召回 1.1%、河流 25.6%（对比三调地类），根因是滑窗 + 50㎡ 最小面积 + 窄线状几何的固有缺陷。
4. **训练样本小且跨域**：仅 67 图/937 标注（以安居/SampleData 为主），与绵阳 0.8m 影像域差异大，泛化不足导致漏检。
5. **语义分割头闲置**：训练了 semantic 头但推理只用 instance（find）头，漏了一条提召回路径。
6. **无标准 NIR 波段**：band4 均值 834、max 1381（低于 band3），非 NIR；band4/band3 指数无法区分林地/耕地。
7. **暗色阈值是双刃剑**：`p10<25` 删 400 个暗色林地，但可能误删更暗的湿土/阴影耕地。

### 3.4 输入输出

- **输入**：① SLIC 超像素 gpkg（含 3 旬 30 波段特征）；② 外部承保地块 shp（任意 CRS，含 `XZMC` 乡镇 / `CJMC` 村 / `ZWMC` 真值 / `TBMJ` 投保面积 / `TBJJ` 期次 / `YEAR_`）；③ 模型 pkl。
- **输出**：
  - `{name}_A_赋值`：主交付，承保地块 + 作物标签 + 11 个质量字段。
  - `{name}_B_质检`：质检附件，超像素套合状态。
  - 格式 `.gpkg/.csv/.shp` 三份。
- **11 个质量字段**：`parcel_id / area_m2 / ndvi_max / ndvi_flag / predicted / prdct_lbl / max_prob / conf_flag / prdct_cf / buf_pixel / px_statu`。

### 3.5 使用方法与关键口径

预测 + 套合（主路径，`predict_slic_overlay.py`）：

```bash
python predict_slic_overlay.py \
  --slic slic_前进村.gpkg \
  --external 前进村_耕地地块.gpkg \
  --model dachun_binary_23counties_3dekad_wide.pkl \
  --model2 dachun_binary_2dekad_wide.pkl \
  --model3 dachun_binary_2dekad_d11d14_wide.pkl \
  --filter cropland_filter_general.pkl \
  --output 前进村结果 \
  --name 前进村_wide_v4
```

地块级直接预测（`predict_dachun_gee.py`，读任意地块 shp）：

```bash
python predict_dachun_gee.py \
  --input <地块.shp> \
  --output <输出目录> \
  --model dachun_binary_23counties_3dekad_wide.pkl
```

关键口径：

| 项 | 口径 |
|---|---|
| 关键 3 旬 | D04（5 月上）、D11（7 月中）、D14（8 月中），20 天宽窗口 |
| GEE 数据源 | `S2_SR_HARMONIZED` + SCL 云掩膜（3/8/9/10）+ median 合成 |
| 特征提取 | `reduceRegions(mean, scale=10, tileScale=4)` |
| 判定链 | `buf_pixel<1` → 无覆盖；`ndvi_max<0.30` → 非植被；`max_prob<0.60` → 不确定；否则 `prdct_lbl`（水稻/玉米） |

### 3.6 数据与结果位置

- **承保地块**：`待训练数据绵阳市\绵阳市\{县}\矢量\{县}.shp`（如 `盐亭县.shp` 8255 块、`江油市.shp` 7542 块）。
- **结果目录（本地）**：`梓潼结果\`、`三台结果\`、`江油结果\`、`盐亭结果\`、`平武结果\`。
- **命名格式**：`{县}_{镇}_wide_v4_A_赋值.gpkg`（主交付）、`{县}_{镇}_wide_v4_B_质检.gpkg`（质检）。

### 3.7 潜在问题

1. **云覆盖缺失**：盐亭 4 乡镇首轮 18%~55% 缺（文通镇最重），加宽窗口 + 双两旬兜底后显著下降，但小地块仍会某旬被云全遮。
2. **小地块特征不足**：地块在哨兵 10m 上 `buf_pixel<3` 时噪声大、易判「不确定/过小」。
3. **SLIC 超像素 ≠ 真实田埂**：会切碎/粘连，套合需设重叠面积阈值与容差。
4. **跨县泛化下降**：23 县全量 Acc=0.904 / 留一县 0.877，低于 5 县（0.928），山区县更难。
5. **GEE 依赖**：特征提取/预测强依赖 GEE 账号 + 哨兵访问，无 GEE 时需回退本地下载瓦片。
6. **版本割裂历史**：大春预测曾用本地单景、训练用 GEE median，口径不一致；现 `predict_dachun_gee.py` 已补齐 GEE 预测对齐训练。

## 四、前后置衔接点（合并关键）

| 项 | 现状 |
|---|---|
| 衔接接口 | 后置 `predict_dachun_gee.py --input` 吃「地块 shp」，前置 SAM3 恰好产出「耕地地块 shp」，格式天然对得上 |
| 前置产出 | 耕地 shp（`class=farmland`）+ 水体 shp（`class=water`） |
| 后置需要 | 地块边界 shp（承保地块或任意地块）→ 哨兵特征 → 水稻/玉米 |
| 合并方向 | SAM3 耕地地块 → 作物识别；水体地块直接标 water 不进作物分类 |

**合并前需注意的差异**：

1. **地块尺度**：SAM3 地块是 0.8m 高分分割，最小 44㎡；哨兵 10m 一个像元 100㎡，SAM3 小地块在哨兵上只有 1~2 像元，`buf_pixel<3` 会大量触发（与后置小地块问题叠加）。
2. **字段缺失**：SAM3 地块无承保字段（村编码/投保面积），「承保地块版」需套合回承保地块才能补上。
3. **数据范围**：宝珠村（前置试点）无承保地块（承保在江油 4 镇等 15 乡镇，不含宝珠村），「承保地块版」需到有承保地块的乡镇验证。

## 五、路径 A 实测验证（09-09）

用宝珠村 SAM3 耕地 shp（`result_baozhucun_v10_fix2.shp`，6675 块，全 class=farmland，CRS EPSG:4523）直接跑 `predict_dachun_gee.py`（主模型 `dachun_binary_23counties_3dekad_wide.pkl`），零代码改动，验证尺度错配。

| 指标 | 结果 |
|------|------|
| 全部地块「过小(<3px)」占比 | **30.7%**（2048/6675） |
| buf_pixel 中位数 | 4 像元 |
| 面积<300㎡ 地块占比 | 24.9%（1664 块） |
| 其中「过小」率 | **87%**（1447/1664） |
| 其中「无覆盖」率 | 19.7%（327/1664） |
| 面积≥300㎡ 地块占比 | 75.1%（5011 块） |
| 其中「过小」率 | 12%（601/5011），88% OK |

**结论**：SAM3 分得太细，小地块在哨兵 10m（1 像元=100㎡）上不可靠——<300㎡ 地块 87% 过小、近 1/5 直接无覆盖。路径 A 直接串会损失近 1/3 地块，**印证方案 B 是正确选择**：SAM3 出耕地边界/掩膜，作物识别以承保地块（面积较大）为单元。

## 六、环节部署分析（哪些放服务器）

| 环节 | 计算资源 | 部署位置 |
|------|---------|---------|
| SAM3 分割 / 耕地·水体识别 | GPU（8×RTX4090） | **服务器（必须）** |
| 哨兵特征提取（reduceRegions） | GEE 云端 | **GEE**（计算在 Google，Python 提交脚本可放服务器或本地） |
| 特征工程（155 维 compute_feature_matrix） | 轻量 CPU | 服务器 / 本地 |
| LightGBM 推理 | 轻量 CPU | 服务器 / 本地 |
| 判定链 / 套合 / 交付 C | 轻量 CPU | 服务器 / 本地 |

**结论**：除「GEE 云端计算」外，其余环节均可放服务器，形成**服务器一条龙**：

```
SAM3 分割(GPU) → 耕地 shp → GEE 特征(云端算, 服务器提交) → 特征工程+推理(CPU) → 套合 → 交付 C
```

本地只做开发、调试、模型训练、结果查看。**前提**：服务器需装 `ee` + GEE 认证 + `lightgbm` + `geopandas`，并把模型 pkl + 代码同步过去（git clone）。

| `{name}_A_赋值.gpkg` | 主交付 | id/class/area_m2/prdct_cf/conf_flag/max_prob/px_statu |
| `{name}_B_质检.gpkg` | 全量质检明细 | SAM3 原始 + 11 质量字段（不筛选） |
| `{name}_C_交付.gpkg` | 交付标准 9 列 | 序号/村编码(留空)/村名称(留空)/期数时间/五级标的编码/五级标的名称/地块唯一编码/实际面积亩 |

**C 口径**：村编码/村名称留空（等套合回承保地块再补）；实际面积亩 = area_m2÷666.667；五级标的编码 = 水稻 AA0000 / 玉米 AA0007，非作物（无覆盖/不确定/非植被）留空。

**宝珠村验证**（6675 块）：玉米 AA0007=5490、水稻 AA0000=454、非作物编码留空=731（无覆盖 367 + 不确定 330 + 非植被 34）。

## 八、SAM 前置产品设计（核心层 / UI 解耦 + 单机桌面应用）

### 8.1 产品形态决策

| 决策项 | 结论 |
|--------|------|
| 部署位置 | Windows 用户机（要求 NVIDIA GPU） |
| 产品形态 | **单机桌面应用 + UI**（非 Web，非纯 cmd） |
| UI 框架 | PySide6（后续实现） |
| 分发方式 | conda 环境打包分发 |
| 架构 | **核心层（cmd）与 UI 层解耦**，核心层可独立运行，UI 仅做封装 |

### 8.2 端到端输入 / 输出定义

整体数据流：**前置 SAM 产品（影像→地块）→ 后置作物识别（地块→A/B/C）**。

**① 前置 SAM 产品**

| 环节 | 内容 |
|------|------|
| 输入 | ① DOM 影像地址（GeoTIFF，4 波段 0.8m，EPSG:4523）；② 候选村信息（内置村界库按名勾选 / 上传村界 shp，二选一） |
| 输出 | 带**村信息 + 分割地块信息**的 shp，三类（见下表） |

| 文件 | 内容 |
|------|------|
| `{name}_耕地.gpkg` | 耕地地块（class=farmland） |
| `{name}_水体.gpkg` | 水体地块（class=water） |
| `{name}_合并.gpkg` | 耕地+水体合并，`class` 区分 |

三类均带 `village_code`（村编码）/ `village_name`（村名称）字段，并按所选村界范围裁剪。

**② 后置作物识别模块**

| 环节 | 内容 |
|------|------|
| 输入 | 前置输出的带村信息地块 shp（`{name}_耕地.gpkg`，或合并里 `class=farmland`） |
| 输出 | A/B/C 三类 shp：`{name}_A_赋值` / `{name}_B_质检` / `{name}_C_交付`（9 列交付标准，村编码/村名称透传） |

### 8.3 核心层 `sam_pipeline.py`（已实现并测试）

统一入口，6 步流水线：

```
资源检测 → 村界加载 → 村界↔影像匹配校验 → SAM3 推理(耕地/水体) → 地块归属村 → 输出三类 shp
```

| 模块 | 函数 | 说明 |
|------|------|------|
| 资源检测 | `detect_resources()` | GPU（`torch.cuda.device_count`）+ CPU（`multiprocessing.cpu_count`），无 torch/CUDA 降级不报错 |
| 村界加载 | `load_villages()` | 内置库模式先按影像范围过滤（规避全省重名村）再按名勾选；上传模式直接读 |
| 匹配校验 | `check_village_image_match()` | 影像可 ≥ 村界（ok）；不可 < 村界（partial 警告）；村界在外（outside 报错终止） |
| SAM3 推理 | `run_sam3()` | 调 `geo_infer_v10_multigpu.py`，分别跑 farmland / water |
| 村归属 | `assign_villages()` | 地块 ∩ 村界**最大重叠面积**归属 |
| 输出 | `output_shps()` | 耕地 / 水体 / 合并三 gpkg，按村界联合范围裁剪 |

**关键口径**：
- 统一坐标系 `EPSG:4523`（影像、上传村界、输出均此系；内置库 4490 自动转）。
- 村编码/名称字段自动识别：内置库 `村级码/村级名`，上传 `ZLDWDM/ZLDWMC`。
- 匹配容差 15m（吸收边界舍入误差，宝珠村实测边界差 5.4m 不误报）。
- SAM3 矢量化阶段水体 class 误标 farmland，`_read_sam3_result()` 强制统一。

**本地测试（跳过推理）**：单村上传模式输出 耕地 4138 / 水体 395 / 合并 4533，100% 归属宝珠村（村编码 5107811252060000000）；3 村内置库模式正确过滤到仅宝珠村。

### 8.4 作物识别模块对接

前置输出（带村信息的地块 shp）→ `make_abc_sam3.py` → A/B/C 三件套，链路不变。

**已微调**：`make_abc_sam3.py` 的 `build_c()` 改为**从输入 shp 读 `village_code`/`village_name` 字段透传**（无字段或空值则留空），其余逻辑不动。

### 8.5 改动量评估

| 部分 | 改动 |
|------|------|
