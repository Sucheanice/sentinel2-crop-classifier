## 五、技术路线

### 5.1 特征口径（GEE）

- 影像：`COPERNICUS/S2_SR_HARMONIZED` + SCL 云掩膜（3/8/9/10/11）
- 合成：median 旬合成，**2025 全年 36 旬**
- 指数（**15 个 × 36 旬 = 540 维**，2026-10-14 由 9 个扩展到 15 个）：

| 指数 | 公式 | 用途 |
|---|---|---|
| NDVI | (B8−B4)/(B8+B4) | 绿度主指标 |
| EVI | 2.5(B8−B4)/(B8+6B4−7.5B2+1) | 高生物量（**云残留噪声大，不进指纹**） |
| SAVI | 1.5(B8−B4)/(B8+B4+0.5) | 土壤调整绿度 |
| RVI | B8/B4 | 比值植被指数 |
| NDWI | (B3−B8)/(B3+B8) | 水体 / 含水 |
| MNDWI | (B3−B11)/(B3+B11) | 水体（含建筑抑制） |
| LSWI | (B8−B11)/(B8+B11) | 叶片含水 |
| NDRE | (B8−B5)/(B8+B5) | 红边叶绿素（果树冠层敏感） |
| NDI45 | (B5−B4)/(B5+B4) | 红边—红（作物胁迫） |
| NDII | (B8−B11)/(B8+B11) | **与 LSWI 同式**，按用户点名保留 |
| CVI | B8·B4/B3² | 叶绿素 |
| TCARI | 3[(B5−B4) − 0.2(B5−B3)(B5/B4)] | 叶绿素吸收比值 |
| IRECI | (B7−B4)/(B5/B6) | 倒红边叶绿素 |
| MTCI | (B6−B5)/(B5−B4) | MERIS 陆地叶绿素 |
| GCVI | B8/B3 − 1 | 绿度叶绿素 |

- 涉及波段：B2、B3、B4、B5（红边1）、B6（红边2）、B7（红边3）、B8、B11
- ⚠️ **540 波段会触发 ee 的 `RecursionError`**（表达式树过深）。已在 `build_stack()` 里改成
  「**每旬先 `ee.Image.cat` 合成一个 15 波段影像、再拼 36 段**」，嵌套深度从 540 降到 36，
  并加 `sys.setrecursionlimit(100000)`。
- ⚠️ **GEE `sample()` 单次上限 5000 要素**。要更多点必须分多次不同 `seed` 抽（`sample_region()`）；
  一次性要 8000 点会被中止并**导致整批不落盘**，现已改为按 ≤4500 分次 + **每镇分步落盘**。

### 5.2 指纹指标（从 540 维派生 → **98 维**）

**14 个指数**（不含 EVI）× 7 类指标 = 98 维：

| 类别 | 定义 |
|---|---|
| 冬 / 春 / 夏 / 秋 _指数 | 各季月均（冬 12/1/2、春 3/4/5、夏 6/7/8、秋 9/10/11） |
| 振幅_指数 | 7+8 月均 − 12+1+2 月均 |
| 冬稳定_指数 | **12 月各旬的标准差** —— 注意：这是**离散度**指标，见 §6.5 隐患 |
| 成熟期_指数 | 10+11 月均（柑橘 / 蜜柚成熟期） |

### 5.3 来源样本的「常绿像元」筛分（`citrus_pomelo_clean.py`）

来源产区里必然混着非目标作物，**先用「全年常绿」判据把目标作物像元筛出来再用**：

```
常绿像元 = 全年 12 个月的月度 NDVI 都 ≥ 0.40
```

原理：柑橘 / 柚是常绿，**每个月都绿**；水稻、玉米、油菜在泡田 / 收割 / 换茬期必然掉到 0.2 附近。

> **v1 判据已废弃**：原用「冬季 NDVI 高 + 振幅小」+ 在 KMeans 结果里取最绿的一群。
> 两个问题：① 结果**依赖聚类怎么分**（同一批 785 个天宝园点，5 产区一起聚类算 48%、只 2 产区算 25.7%）；
> ② 会**把「冬小麦+夏玉米」两熟田误收进来**（冬季 0.4、夏季 0.6、振幅仅 0.2，全部通过）。

### 5.4 打分与分级 —— **双库对照（同镇自校准）**

单一「像不像蜜柚」的打分会失效：98 维里一大批维度（`冬稳定_*`、`MNDWI_*`）反映的是**地理 / 云况**，
**同县取样**时目标与库本来就相似 → 全部拿高分（实测黎雅 98.6% 被判蜜柚，见 §八 2026-10-16）。改为**双库对照**：

1. **正库** = 来源产区（自净）的蜜柚 / 柑橘指纹；
2. **对照库** = **本镇内已被判为水稻 / 玉米的耕地块**（同镇同地理、同云况）；
3. 逐块算到两库的**归一化偏离** `d = mean_维( |tgt − 库中位| / 库MAD )`；
4. `score = d_neg / (d_pos + d_neg)`（0~1，**>0.5 表示比本镇大春作物更像该水果**）
   —— 地理 / 云况维度在两库间**自动抵消**，无需手工挑维度；
5. 分级：**高 ≥0.62 / 中 0.50~0.62 / 低 <0.50**。

**阈值锚定**：蜜柚库样本自己 score 中位 0.69~0.72、P10 0.54~0.58；同镇水稻 / 玉米中位仅 0.29~0.32
→ 取 0.50 = 等距分界、0.62 = ≈库样本下四分位。

**实装**：`成果代码/merge_fruit_into_delivery.py`（`block_fit_dist` + 双库），只把「高 / 中」写入编码列。

## 六、已知风险（必须前置说明）

1. **10 m 哨兵分不开"果园"与"耕地"** —— 已两次实证：
   - §9.19（本仓库工作记录）：盐源苹果 vs 小金荒地，物候曲线几乎完全重合；
   - §9.22：用江油 244 块**真实调查果园边界**做有监督验证，果园冬季 NDVI 中位 0.421、耕地_玉米 0.393，任何阈值下命中率几乎相同；单特征最高 AUC 仅 0.726（10–11 月均）。
   → **本任务的"三级嫌疑"只能作为人工复核的排序依据，不能当作确权结论。**
2. **盆地冬季云厚**：1 月与 2 月上旬在盆地区有效率为 0%，"冬季判据"实际只剩 12 月。
3. **来源产区无地块边界**：蒲江 / 丹棱 / 东坡 / 资中这些产区我方没有果园图斑，只能做**点采样**（受"镇内非柑橘占比"稀释）。梓潼蜜柚同理。后续若有园区边界应替换。
4. **柑橘 / 蜜柚同为常绿**：二者在 10 m 物候上高度相似，靠物候难分彼此，最终仍需高分影像的株行距 / 树冠形态区分。
5. **⚠️「冬稳定_*」是最强分辨指标，但它很可能不是作物生理差异** —— 98 维指纹里，柑橘库 vs 蜜柚库可分性最高的几乎全是 `冬稳定_*`（12 月各旬 NDVI 的标准差），柑橘 vs 耕地代理也是它最突出。但两个库的**地理位置 / 云况完全不同**：
   - 柑橘库在**蒲江盆地 / 眉山平原**（海拔低、冬季多云）
   - 蜜柚库在**梓潼丘陵**（海拔高、冬季更晴）
   冬季晴空/多云的比例不同，直接改变 12 月旬间 NDVI 的波动大小。**这个差异是地理 + 云况造成的，换成同地同期影像才会消失。** 后果：把「冬稳定」当主判据，会退化成「按地理区域分类」而非「按作物分类」——目标镇若与来源库地理相近就整体偏高。
   → **处置**：① 打分时对 `冬稳定_*` 降权或单独看；② 来源库与目标镇尽量取**同海拔 / 同云况带**；③ 报告里必须标明该指标的不确定性。
