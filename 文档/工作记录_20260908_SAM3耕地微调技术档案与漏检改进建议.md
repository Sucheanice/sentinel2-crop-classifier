> 用途：梳理"针对耕地微调 SAM3"这一件事的完整技术细节（①~⑬），并针对宝珠村测试发现的"漏识别耕地"问题提出改进建议。

## 〇、一句话总览

- 这是一次**冻结视觉/语言双编码器**的 SAM3 微调，把"交互式文本分割模型"适配成"农田地块实例提取器"。
- 模型同时训练了**实例检测头（find）**和**语义分割头（semantic）**，但推理脚本只用了**实例检测头 + 文本 Prompt "farmland"**。
- 宝珠村测试用的是**简化版推理脚本（方法四，纯文本 prompt）**，而服务器上其实另有一套**生产版 v10 管线**（文本 + SLIC 点提示 + 框精修），后者才是为"提召回、防漏检"设计的。

## 五、⑤ Ground Truth（真值制作流程）

1. **人工勾画**：用 ArcGIS Pro / QGIS 在影像上勾画多边形（每块地一个要素，贴边、田埂/沟渠不得画入）。
2. **导出 Shapefile**：必含字段 `FID`(序号)、`id`(类别编号)、`class`(类别名，如 `farmland`)，并带 `.prj` 投影文件。
3. **转 COCO**：`xml2coco.py` 或 `sam3/train/convert_fhapd_to_coco.py` 把 shp 转成 `_annotations.coco.json`（`segmentation` 为 RLE 掩膜，含 `bbox/area/category_id/iscrowd`）。
4. **划分**：train/val/test。

勾画规范详见服务器 `sam3_train/sam3_farmland/样本勾画要求.md`（含 farmland/building/forest 等 7 类的勾画要点与质检清单）。

## 十二、⑫ instance segmentation 还是 semantic segmentation

**结论：两者都训练了，但推理只用了 instance（find）路径。**

训练 config 同时挂了两组损失：

1. **实例检测（find）损失** `loss_fns_find`：
   - `Boxes`（`loss_bbox=5`、`loss_giou=2`）
   - `IABCEMdetr`（`loss_ce=20`、`presence_loss=20`）
   - `Masks`（`loss_mask=200`、`loss_dice=10`）
2. **语义分割损失** `loss_fn_semantic_seg`（`SemanticSegCriterion`）：
   - `loss_semantic_seg=20`、`loss_semantic_presence=1`、`loss_semantic_dice=30`

而推理脚本（方法四 `set_text_prompt`、生产 v10 `set_text_prompt/add_geometric_prompt/add_geometric_points`）全部走的是 `forward_grounding`（find 头，输出 `pred_boxes/pred_logits/pred_masks/presence_logit`），**没有使用语义分割头**。

> 含义：语义分割头（像素级分类，通常对"同质大块/复杂纹理"召回更高）被训练了，但在推理端被闲置，属于潜在的召回提升空间。

## 十四、Prompt 使用机制（回答"是不是只用文本 farmland"）

**是用了 Prompt，但不止"简单文本 farmland"这一种，取决于用哪套脚本：**

1. **文本 Prompt 是必选项**：两条管线都会调用 `set_text_prompt(prompt="farmland")`，由文本编码器把 `"farmland"` 编码成语言特征，再与图像特征做跨模态匹配（grounding），输出实例 mask + score。

2. **简化版脚本（宝珠村测试）只用了文本 `"farmland"`**，没有任何点/框提示。

3. **生产版 v10 是"混合提示"**，在文本初筛之外还叠加：
   - **SLIC 超像素自适应点提示**：把图像切成超像素，取"距超像素边界最远点"作为 SAM 正样本点，一次批量解码，专门兜底"文本漏检"的同质大块耕地。
   - **框几何精修**：对中间置信度（`refine_low~refine_high`）的对象，用其预测框作为 box 提示二次解码，改善边界与召回。

所以准确说法是：**文本 `"farmland"` 始终在用；但服务器真正用于生产提召回的，是"文本 + SLIC 点 + 框精修"的混合提示，而非单一文本。**

## 十五、漏识别耕地的原因分析

结合宝珠村实测与代码，漏检主要来自以下几点（按影响排序）：

1. **用了简化版脚本（纯文本 prompt）**：宝珠村测试跑的是 `geotiff_farmland_parcels_context.py`（方法四），只有文本 `"farmland"`，没有 SLIC 点提示和框精修。文本对"同质大块、光谱/纹理多样的耕地"召回天然不足，这是漏检的头号原因。
2. **confidence_threshold 默认 0.5 偏高**：`_forward_grounding` 里 `keep = out_probs > 0.5`，低分耕地被直接丢弃。生产建议阈值是 0.23~0.4。
3. **训练数据小且与目标域不匹配**：train 仅 67 图/937 标注，样本以安居、SampleData 为主；宝珠村是绵阳 0.8m 影像，与训练 0.5m、不同地貌/光谱差异大，泛化不足。
4. **语义分割头被闲置**：像素级分类头（对复杂纹理/大块更鲁棒）训练了但推理没用，只用实例头，少了一条提召回路径。
5. **方法四的过滤参数可能误删耕地**：`min-parcel-pixels=100`、`max-context-area-ratio=0.25`、`max-context-edge-touches=1`、`min-hole-area-m2=50` 等，会把小块/边缘/贴边地块过滤掉。
6. **分辨率不匹配**：输入 0.8m，方法四按 512/1024 窗口切，与训练 1008（0.5m）尺度不一致，可能漏掉小地块。

## 十六、改进建议

### 建议 1（最高优先）：改用生产 v10 管线，而不是方法四

生产管线专门为"提召回"设计（SLIC 点提示 + 框精修 + 多层过滤）。用 `geo_infer_v10.py` 或 `/api/segment_geo`，参考生产参数：

```bash
curl -X POST http://127.0.0.1:<port>/api/segment_geo \
  -F image=@<宝珠村.tif> -F prompt=farmland -F use_sliding=1 \
  -F tile_size=1008 -F core_size=672 -F core_overlap=168 -F stretch=0 \
  -F fine_tile_size=588 -F fine_overlap=0.25 -F fine_core_size=448 -F fine_core_overlap=112 \
  -F geometric_refine=1 -F refine_low=0.23 -F refine_high=0.60 -F max_refine_boxes=20 \
  -F slic_points=1 -F slic_segments=64 -F slic_compactness=10 \
  -F slic_min_distance_m=3.0 -F slic_points_fine=0 -F slic_max_points=128 \
  -F fill_holes=1 -F hole_area_pixels=268 -F simplify_tolerance=1 \
  -F mask_smooth_sigma=1.0 -F remove_overlap=1 -F min_area_m2=67 \
  -F merge_touching=1
```

（如需农田范围约束再加 `-F restrict_shp=<农田范围>.shp`。）

### 建议 2：降低置信度阈值

把 `confidence_threshold` 从 0.5 降到 **0.3~0.4**（漏检严重可用 0.23），代价是误检略增，需配合后面的过滤旋钮。

### 建议 3：多 Prompt 融合 / 择优

文本措辞对召回影响大，TUNING_GUIDE 建议对典型图试多个候选：

```text
farmland / agricultural land / cropland / field / cultivated area / parcel
```

可用 5~10 张典型图跑全部候选，人工对比选最优；或对多个 prompt 的 mask 取并集提召回。

### 建议 4：补充目标域样本继续微调

- 用宝珠村 / 绵阳当地影像补充勾画样本（参照 `样本勾画要求.md`，farmland ≥200 块）。
- 统一到 0.5m 分辨率再训练（或将 0.8m 影像重采样到 0.5m），减少尺度不匹配。
- 样本尽量覆盖：裸土、翻耕地、不同作物、覆膜田、连片大田与分散小块、田埂边缘地块等多样性。

### 建议 5：放宽方法四的过滤参数（若仍用方法四）

若必须用简化脚本，先放宽漏检相关参数：

- `--min-parcel-pixels` 调小（如 50~60）。
- `--max-context-edge-touches` 调大（如 2~3），减少贴边地块被删。
- `--max-context-area-ratio` 调大（如 0.4），保留连片大块。

### 建议 6：启用语义分割头的推理路径（中长期）

语义分割头已训练但未用。可增加"像素级分类 → 矢量化"的推理分支，或把 instance 与 semantic 结果融合，进一步提召回。这需要改 `geo_infer`/`inference` 代码，属于中长期优化。
