## 三、交付标准三类导出

### 口径（复刻 `成果数据/交付标准数据格式/马角镇前进村*.xlsx`）

9 列固定：`序号 | 村编码 | 村名称 | 期数（时间） | 五级标的编码 | 五级标的名称 | 地块唯一编码 | 地块边界（WGS） | 实际面积/亩`

三类各自一套编码体系：

| 类别 | 五级标的编码 / 名称 | 数值口径 |
|---|---|---|
| **地块边界** | 农业生产分类：`A01` 耕种地块、`B03` 鱼塘 | 耕地 + 水塘合并，19,376 块 |
| **大春作物** | 标的编码：`AA000000` 水稻、`AA000700` 玉米 | 只保留判为水稻/玉米的 15,343 块 |
| **用地分类** | 国土空间用地分类：`A0101` 水田、`A0103` 旱地、`A1104` 养殖水面 | 19,376 块 |

对齐细节：

- 村编码 12 位整数；村名称 = 村级名 + "委会"（参照写「前进村委会」）
- 地块唯一编码 = `G` + 村编码 + 6 位序号，**按村独立编号**
- 地块边界（WGS）= `MULTIPOLYGON(((...)))` WKT，WGS84 **全精度**，类型名后与坐标逗号后都不带空格（逐字对齐参照）
- 实际面积/亩 = `area_m2 × 0.0015`（等价 /666.6667，与参照数值口径一致）
- 序号 1..N 连续

### 与参照的已知差异（需业务确认）

| 项 | 参照 | 我们的处理 |
|---|---|---|
| 期数（时间） | `2026-08-20` | 照填 `2026-08-20`，**占位**，待确认本任务应填什么（`--period` 可改） |
| 村名称 | 只出现"XX村委会" | 村 → 补"委会"；**社区类**（如涪滨社区）保持原名，参照无样例 |
| 地块唯一编码编号基准 | 三份文件各自 1..N 独立重编号（同一编码在三份里不一定指同一地块） | 改为**按村编号、三份文件同一地块编码一致**（"唯一编码"应稳定） |
| 标的编码位数 | 交付 excel 是 8 位（`AA000700`） | 按交付 excel 用 8 位；标准文档其实是 6 位（`AA0007`），口径不一致 |

### 能力缺口

`用地分类` 参照里有 **15 类**（水田/水浇地/旱地/园地/林地/草地/养殖水面/农田水利设施用地…），我们只出得了 **3 类**——前序只做了"耕地地块判别分割"和"水体判别"两件事，园地/林地/草地/沟渠都没有来源。

另外 **水田/旱地是推导的**：判为水稻的算水田（A0101），其余耕地算旱地（A0103），符合"水田种稻"常理，但不是真做了水田/旱地细分。要严格得用 GEE 淹水信号（`common.py` 里已有 LSWI 淹水检测思路）另做一步。

### 关于"林地"

已确认现有 `landuse_6village_model.pkl` 是**无人机 8.9 cm RGB 特征模型**（18 个特征全是 RGB 派生），不是 GEE 模型；其训练影像 `F:\YXX\江油市影像` 与标注 `F:\0421给yxx\提交成果` 在本机均不存在。且前序未产出林地层。**结论：本批不做林地识别。**

## 五、前序数据检查与处理（水体/耕地交叉 + 鱼塘/水体细分）

拿到前序数据后先做一次交叉检查，脚本 [check_frontend_layers.py](../../成果代码/check_frontend_layers.py)。

### 5.1 耕地层里混进了水体块（本次发现的 bug）

SAM3 用 `farmland` 提示也会在水面（尤其带水草/藻类的塘）上响应，这些块被当成耕地、还参与了作物赋值。

| 检查项 | 结果 |
|---|---|
| 耕地层被水体覆盖 ≥50% 的块 | **86 块 / 327.5 亩**（其中 76 块 ≥95%） |
| 其中被判成作物的 | **68 块 / 276.9 亩**（水稻 65 + 玉米 3） |

处理：这些块的水体面已由水体层表达，因此**从耕地类剔除、不做作物赋值**。剔除后耕地层 19,079 → **18,993 块**；作物赋值随之少了 68 块（水稻 6,025→5,960、玉米 9,318→9,315）。

> 说明：GEE 的 zonal 特征是逐块独立计算的，剔除这些块不会影响其它块的结果，所以是直接过滤已有赋值结果，没有重跑 GEE。

### 5.2 水体层细分「鱼塘」和「水体」

交付口径里鱼塘属养殖地块（农业生产分类 `B03` / 用地分类 `A1104` 养殖水面），河流、水库等属其他水面（用地分类 `B1199`），两者不是一回事。判据：**形状方正**（面积 / 最小外接旋转矩形面积）+ **面积较小**。

默认阈值：方正度 ≥ 0.6 且 面积 ≤ 5 亩 → 鱼塘。

| 类别 | 块数 | 面积 | 方正度中位 | 面积中位 |
|---|---|---|---|---|
| 鱼塘 | 255 | 397.6 亩 | 0.78 | 1.26 亩 |
| 水体（其他水面） | 42 | 481.2 亩 | 0.67 | 7.39 亩 |

判据散点图 + 分布图：`前序检查/太平镇_water_preview.png`。阈值都在命令行上（`--square-min` / `--area-max-mu` / `--water-ratio`），看后觉得不合适可调完重跑。

**正确的流水线顺序**（本次已按此产出）：

```
拼接地块层 → 前序检查（剔水体块 + 水体细分）→ 村界归属 → 作物赋值 → 交付三类导出
```

## 六、代码与命令

| 脚本 | 用途 |
|---|---|
| [merge_farmland_shp.py](../../成果代码/merge_farmland_shp.py) | 跨影像拼接通用（`--pattern` 换文件名匹配即可用于水塘等其它地类层；额外属性字段原样透传） |
| [check_frontend_layers.py](../../成果代码/check_frontend_layers.py) | **前序数据检查与处理**：耕地/水体交叉检查、剔除耕地层里的水体块、水体细分鱼塘/水体（阈值可调 + 出判据图） |
| [export_delivery_xlsx.py](../../成果代码/export_delivery_xlsx.py) | 按交付标准导出三类 xlsx（`--also-gpkg` 同时出 gpkg 镜像便于 GIS 核图） |
| [make_abc_sam3.py](../../成果代码/make_abc_sam3.py) | 耕地 shp → GEE 特征 → 作物判断 → A/B/C 三件套 |

```powershell
# 拼接（耕地 / 水塘同一套）
python merge_farmland_shp.py --dir "...\26\farmland" --out "...\绵阳_farmland_merged.shp"
python merge_farmland_shp.py --dir "...\26\pond" --pattern "*_pond.shp" --out "...\绵阳_pond_merged.shp"

# 前序数据检查与处理（剔水体块 + 水体细分，阈值可调）
python check_frontend_layers.py --farmland "...\绵阳_farmland_merged.shp" --pond "...\绵阳_pond_merged.shp" `
    --out-dir "...\26\前序检查" --prefix 太平镇 --plot

# 作物赋值（需 agri_local 环境 + GEE 已认证 + PYTHONPATH 指向归档_作物分类项目）
python make_abc_sam3.py --input "...\太平镇_耕地_带村界.gpkg" `
    --model "...\模型\dachun_binary_23counties_3dekad_wide.pkl" `
    --output "...\26\作物赋值" --name 太平镇

# 交付三类
python export_delivery_xlsx.py --farmland "...\太平镇_B_质检.gpkg" --pond "...\绵阳_pond_merged.shp" `
    --village-lib "...\四川省_村界.shp" --out-dir "...\26\交付" --prefix 太平镇 --also-gpkg
```

环境：`D:\miniconda3\envs\agri_local\python.exe`（ee 1.7.40 / geopandas 1.1.4 / numpy 2.4.6），需 `PROJ_LIB` 指向该环境的 proj。
