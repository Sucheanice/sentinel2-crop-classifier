# 代码审查报告

**项目**：基于 Sentinel-2 卫星影像的农作物分类项目
**审查日期**：2026-07-24
**审查范围**：项目根目录下 6 个 Python 脚本

| 脚本 | 作用 |
|------|------|
| `crop_s2_to_dom.py` | 影像裁剪（按 DOM 范围） |
| `extract_pixels_v2.py` | 像素级特征提取（分区均值 + 云掩膜） |

| `pipeline_cropped.py` | 裁剪数据一体化流水线 |

## 一、严重问题（建议优先修复）

### 1. 正则表达式双重转义错误（标签清洗结果不一致）

- **位置**：`pipeline_cropped.py` 第 39 行
- **问题**：

  ```python
  # pipeline_cropped.py（错误）
  s_norm = re.sub(r'[\\(（][^)）]*未种[^)）]*[\\)）]', '(未种)', s_norm)
  ```

  ```python
  # extract_pixels_v2.py / optimize_model_v2.py / train_save_model.py（正确）
  s_norm = re.sub(r'[\(（][^)）]*未种[^)）]*[\)）]', '(未种)', s_norm)
  ```

- **影响**：在 raw string 中 `\\(` 表示字面反斜杠加左括号，而非转义左括号。`pipeline_cropped.py` 的标签清洗规则与其它三个脚本不一致，会导致同样的原始标签清洗出不同的类别名，最终训练类别数、样本分布都不同。
- **建议**：统一为 `r'[\(（]...'`，与其它脚本保持一致。

---

### 2. 逐地块栅格化导致性能极差

- **位置**：`pipeline_cropped.py` 第 86–106 行
- **问题**：对每个地块单独调用 `rasterize`，每次都生成全图大小的 mask：

  ```python
  for idx, row in gdf.iterrows():
      mask = rasterize([(geom, 1)], out_shape=(band_data['B02'].height, band_data['B02'].width), ...)
      px_count = np.count_nonzero(mask)
  ```

- **对比**：`extract_pixels_v2.py` 第 139 行是一次性栅格化所有地块（`rasterize_labels`），用 `np.bincount` 统计分区均值，速度快几十倍。
- **影响**：地块数多时（数千到数万），运行时间从分钟级恶化到小时级。
- **建议**：改用 `extract_pixels_v2.py` 的批量栅格化 + `bincount` 分区统计方案。

---

### 3. 全图读入内存，易导致 OOM

- **位置**：`pipeline_cropped.py` 第 269–286 行（step3_predict）
- **问题**：一次性 `read(1)` 所有场景的所有波段：

  ```python
  for si in range(n_scenes):
      blue  = readers[si][0].read(1).astype(np.float32)
      green = readers[si][1].read(1).astype(np.float32)
      ...
  X_block = np.stack(feature_blocks, axis=-1)  # 内存峰值极高
  ```

- **对比**：`predict_crop_map_v2.py` 第 59–93 行按 1024×1024 分块读取预测。
- **影响**：多场景、大范围影像时直接内存溢出。
- **建议**：复用 `predict_crop_map_v2.py` 的分块（Block-wise）预测逻辑。

---

### 4. SUMMARY 打印逻辑混乱，引用了不存在的属性

- **位置**：`optimize_model_v2.py` 第 209 行
- **问题**：

  ```python
  print("  XGBoost %s CV: %.4f (train: %.4f, gap: %.1f%%)" % (
      best_name,
      best.cv_avg if hasattr(best, 'cv_avg') else ...,   # XGBClassifier 无 cv_avg 属性
      ...,
      ...  # 嵌套三元，gap 计算与上面打印的 best 可能不对应
  ))
  ```

- **影响**：
  - `best.cv_avg` 永远走 `hasattr` 为 False 的分支，代码冗余；
  - 嵌套三元表达式 `xgb1_train if best_name=='v1' else xgb2_train` 与 `best` 实际选择逻辑重复，但 gap 用的训练集和 CV 集可能不匹配（当 v1、v2 中某个 `cv_scores` 未被选为 best 时）。
- **建议**：拆成普通变量后再格式化输出：

  ```python
  if best_name == 'v1':
      cv_mean, train_acc = xgb1_scores.mean(), xgb1_train
  else:
      cv_mean, train_acc = xgb2_scores.mean(), xgb2_train
  print("  XGBoost %s CV: %.4f (train: %.4f, gap: %.1f%%)" % (
      best_name, cv_mean, train_acc, (train_acc - cv_mean) * 100))
  ```

## 二、中等问题（效率 / 可维护性）

### 5. 同一文件重复打开两次

- **位置**：`extract_pixels_v2.py` 第 177–185 行
- **问题**：

  ```python
  with rasterio.open(tif_path) as band_ds:
      band_data = band_ds.read(1)

  if band_data.shape != labels_full.shape:
      with rasterio.open(tif_path) as band_ds:   # 又打开一次
          band_data = band_ds.read(1, out_shape=(...), resampling=Resampling.bilinear)
  ```

- **建议**：在同一个 `with` 块内根据 shape 判断是否需要重采样。

---

### 6. 函数内部 import

- **位置**：`optimize_model_v2.py` 第 21 行 `import re, math`；`train_save_model.py` 第 36 行 `import os`
- **建议**：移到文件顶部，符合 PEP8，也避免运行时才发现缺失依赖。

---

### 7. 多脚本间大量重复代码

| 重复函数 | 出现位置 |
|----------|----------|
| `clean_labels` / `clean_labels_strict` | `extract_pixels_v2.py`、`optimize_model_v2.py`、`train_save_model.py`、`pipeline_cropped.py`（共 4 处，逻辑相同） |
| `compute_indices`（EVI/NDWI/SAVI） | `optimize_model_v2.py`、`train_save_model.py`、`predict_crop_map_v2.py`、`pipeline_cropped.py`（共 4 处） |
| 特征选择（RF + argsort top 30） | `optimize_model_v2.py`、`train_save_model.py`、`pipeline_cropped.py`（共 3 处） |
| 标签编码 + 样本过滤逻辑 | 同上 3 处 |

- **风险**：本次发现的 Bug #1 就是因为 `pipeline_cropped.py` 的副本与其它副本不同步。
- **建议**：抽取公共模块（如 `common.py`），包含 `clean_labels`、`compute_indices`、`select_features`、`build_dataset` 等，各脚本统一调用。

---

### 8. 全部硬编码绝对路径

- **位置**：所有脚本顶部的常量定义
- **问题**：形如 `r"E:\工作相关\2026年\0624 待测试数据\待训练数据\..."`，换机器、换目录、换同事都失效。
- **建议**：
  - 短期：顶部用一个 `BASE_DIR` 常量，其它路径基于它拼接；
  - 长期：用 `argparse` 或配置文件（yaml/json）传入。

---

### 9. 纬度范围硬编码（48RWU 判断脆弱）

- **位置**：`extract_pixels_v2.py` 第 30 行
- **问题**：

  ```python
  in_rwu = [c for c in candidates if 30.0 < c[3] < 30.6]
  ```

- **影响**：这是按安居区纬度硬编码的，换到射洪市或其它区域时，SHP 选择会失败（`RuntimeError: No SHP found in 48RWU range`）。
- **建议**：用与 DOM/S2 影像的空间相交判断，或允许用户指定 SHP 路径。

## 三、轻微 / 一致性问题

### 10. `MIN_SAMPLES` 阈值不一致

- `optimize_model_v2.py`、`train_save_model.py` 用 `MIN_SAMPLES = 30`
- `pipeline_cropped.py` 用 `MIN_SAMPLES = 10`

同一项目不同脚本对"最小类别样本数"阈值不一致，会导致类别数和模型结果难以对比。

---

### 11. 缺少错误处理

以下场景会直接抛异常而中断：
- 几何为空（`None` 或 `is_empty`）：仅 `pipeline_cropped.py` 做了判断，其它脚本没有；
- 波段 TIF 缺失：`extract_pixels_v2.py` 有 `MISSING` 提示，其它脚本没有；
- `LabelEncoder` / 交叉验证在样本极少时：`pipeline_cropped.py` 有 try/except，其它没有。

---

### 12. 全部使用 `print` 而非 `logging`

- 无法控制日志级别（INFO/DEBUG/WARNING/ERROR）；
- 长时间运行的任务（栅格化、分块预测）输出无法重定向到文件做排查；
- 建议改用 `logging` 模块，至少对警告和错误分级。

## 五、总体评价

- **功能完整性**：端到端流水线（裁剪 → 特征 → 训练 → 预测）已搭好，技术选型合理（Sentinel-2 + 植被指数 + XGBoost）。
- **主要短板**：
  1. 四个脚本间存在大量重复代码，导致同一逻辑有多份副本，极易产生不一致（本次发现的正则 Bug 就是一例）；
  2. `pipeline_cropped.py` 作为"一体化"脚本，性能实现反而比拆分的脚本差（逐地块栅格化、不分块预测），未复用已有的高效实现；
  3. 硬编码路径和区域参数，跨区域/跨机器部署困难。

建议先修复 P0 问题，再抽公共模块消除重复代码，后续维护成本会显著下降。
