# 果树识别技术流程 — 转移学习冷启动

## 项目概述

基于 Sentinel-2 多时相遥感影像，采用**跨区域迁移学习**策略实现遂宁市果树（不区分树种）识别。核心思路：利用泸州市叙永县的农业保险果树地块（李子+柑橘）作为训练标注，训练 LightGBM 分类器后迁移推理到遂宁全域。

> **版本演进**：v1 RF 3季（F1=0.41）→ v2 LightGBM 3季（F1=0.37）→ v3 LightGBM 4季（F1=0.40）。详见 `工作记录_20260813_果园识别.md`。

**研究区域**：
- 训练区：泸州市叙永县（105.37-105.67E, 27.69-27.80N，276 个果树地块，MGRS 48RWR）
- 推理区：遂宁市（105.25-105.85E, 30.25-30.75N，约 60km×56km，MGRS 48RWU）

**技术路线**：两步走策略
1. **Step 1**（已完成）：AOMC 冷启动 — 用 AOMC 苹果园公开数据在遂宁训练 RF，验证技术链路可行性
2. **Step 2**（已完成）：转移学习 — 叙永 SHP 标注训练 RF，迁移到遂宁推理

## 2. 数据预处理

### 2.1 训练区（叙永）

1. **S2 下载 + 裁剪**：AWS S3 → 本地临时 JP2 → `rasterio.reproject` 裁剪到叙永 SHP 外扩范围，统一 UTM 48N 10m
2. **有效像素检测**：过滤每季云量 > 90% 的无效季节
3. **输出**：每季一个多波段 GeoTIFF（10 波段，deflate 压缩），缓存于 `data/xuyong_s2/`

### 2.2 推理区（遂宁）

1. **逐波段时间序加载**：`run_suining_binary.py` 的 `load_s2_season()` 函数
2. **20m→10m 重采样**：B05/B06/B07/B8A/B11/B12 使用 `rasterio` 的 `out_shape` 参数自动双线性重采样
3. **窗口裁剪**：根据 `SUINING_BOUNDS_WGS84` 投影到 UTM 48N 计算行列窗口
4. **NaN 处理**：<=0 的像素值标记为 NaN
5. **特征缓存**：构建的特征立方体缓存于 `data/suining_features/feature_cube.npy`（68 波段 × 10576×10015 像素，约 28GB float32）

### 2.3 坐标系

- 训练区（叙永）：WGS84 → UTM 48N（EPSG:32648）
- 推理区（遂宁）：本地 S2 已在 UTM 48N（EPSG:32648）
- 最终输出到 DOM：UTM 48N → CGCS2000 GK35（通过 `pyproj` 重投影）

## 3. 特征工程

### 3.1 特征组成（4 季 × 68 维）

| 特征层 | 说明 | 维度 |
|--------|------|:---:|
| **多时相光谱** | 4 季 × 10 原波段（B02-B12） | 40 |
| **植被指数** | 4 季 × 4 VI（NDVI, NDRE, NDMI, EVI） | 16 |
| **物候差值** | 相邻季 NDVI/NDRE 差值（3 组 × 2） | 6 |
| **盛夏纹理** | 末季 NDVI/NIR 局部标准差（3×3 + 7×7） | 4 |
| **地形** | DEM elevation + slope | 2 |
| **合计** | | **68** |

### 3.2 植被指数公式

```
NDVI = (B08 - B04) / (B08 + B04 + ε)
NDRE = (B8A - B05) / (B8A + B05 + ε)   // 红边指数
NDMI = (B8A - B11) / (B8A + B11 + ε)   // 水分指数
EVI  = 2.5 × (B08 - B04) / (B08 + 6×B04 - 7.5×B02 + 1 + ε)
```

### 3.3 纹理特征

仅在夏季（生长季末）的 NDVI 和 NIR（B08）上分别计算 3×3 和 7×7 窗口的局部标准差，捕捉果树冠层纹理区别于均质农田的特征。

### 3.4 季节名称映射

训练区（叙永）和推理区（遂宁）使用不同季节命名，需做映射对齐：

| 遂宁季节 | 叙永季节 |
|----------|----------|
| early_summer | peak_summer |
| late_autumn | late_autumn |
| winter | winter |
| spring | spring |

映射后通过**波段名**（而非位置索引）匹配，确保跨区域特征维度正确对齐。

## 4. 标签构建

### 4.1 正样本

来自 `叙永水果成果数据/result.shp` 的 276 个果树地块，通过 `rasterio.features.rasterize` 栅格化到 10m 网格（约 101 万正样本像素）。

### 4.2 负样本

从 ESA WorldCover 2021 中选择**非 Tree cover 类别**的像素（Cropland 40, Grassland 30, Built-up 50, Bare 60, Water 80 等），与正样本按 `balanced_subsample` 策略采样。

### 4.3 无效值过滤

- 低质量季节（云量 > 90%）对应像素标记为无效
- 任一特征层有 NaN 的像素排除

## 5. 模型训练

### 5.1 分类器：LightGBM（v3）

| 参数 | 值 | 说明 |
|------|-----|------|
| n_estimators | 300 | 决策树数量 |
| learning_rate | 0.03 | 学习率 |
| max_depth | 5 | 最大树深（防止过拟合） |
| num_leaves | 31 | 叶子节点数 |
| subsample | 0.7 | 每棵树行采样比例 |
| colsample_bytree | 0.6 | 每棵树列采样比例 |
| reg_alpha | 1.0 | L1 正则化 |
| reg_lambda | 2.0 | L2 正则化 |
| min_child_samples | 50 | 叶子最小样本数 |
| class_weight | balanced | 平衡正负样本权重 |
| n_jobs | -1 | 全核心并行 |

> 早期版本使用 Random Forest（n_estimators=200, max_depth=18），v3 换成 LightGBM 后 F1 无明显提升（0.41→0.40），但 LightGBM 训练更快。

### 5.2 空间验证

- 方法：**800m 空间块分组 K-Fold**（`GroupShuffleSplit`），按空间块 ID 拆分训练/验证集
- 目的：防止相邻像素信息泄漏，评估模型在**未见过的地理区域**上的泛化能力
- 验证指标：F1、Precision、Recall、Confusion Matrix

> 空间验证是关键设计：普通随机拆分会让相邻像素分入训练和测试集，由于空间自相关性会高估模型性能。

### 5.3 训练流程（`run_transfer_learning.py` 中的 `train_lgb()` 函数）

```
1. 空间块划分：创建 800m×800m 格网 → 逐像素分配 block_id
2. 负采样：正样本匹配 10× 数量的负样本
3. GroupKFold：按 block_id 分 4 折
4. 每折：
   a. 训练 LightGBM
   b. 预测验证折
   c. 计算 F1/Precision/Recall
5. 全量训练：用全部样本训练最终模型
6. 输出：LightGBM 模型 + 特征重要性
```

## 6. 遂宁全域推理

### 6.1 推理流程（`run_transfer_learning.py` 中的 `predict_suining()` 函数）

```
遂宁特征立方体 (68 bands, ~1.06亿像素)
    ↓
波段名对齐 (通过 season_map 映射)
    ↓
选取与训练波段一致的 68 维特征
    ↓
逐像素 LightGBM 预测 (概率 + 二分类)
    ↓
输出: 概率栅格 + 二分类栅格 + SHP 斑块
```

### 6.2 输出产物

| 产物 | 路径 | 说明 |
|------|------|------|
| 二分类栅格 | `outputs/orchard_xuyong_model_suining.tif` | 0/1 二值，阈值 0.5，10m UTM 48N |
| 概率栅格 | `outputs/orchard_xuyong_model_suining_prob.tif` | 0-1 浮点概率值 |
| 全境 SHP | `outputs/shapefile_xuyong_model/orchard_patches.shp` | 294,322 个果树斑块（**v3 过激，需后处理**） |
| 安居区 SHP | `outputs/anju/orchard_patches_anju.shp` | v3 安居区裁切（3,520 斑块） |
| 安居区 SHP（旧） | `outputs/anju/orchard_anju_dom.shp` | v1 旧版安居区（73 斑块，保守） |
| 训练报告 | `outputs/transfer_report.json` | 训练/推理统计 |
| 评估报告 | `outputs/evaluation_report.json` | Step1 AOMC 评估结果 |

### 6.3 后处理（v3.1 新增，`postprocess_orchard.py`）

v3 逐像素预测 + 直接矢量化产生了大量散碎三角和超大异常斑块（最大 129 km²），遂宁近 58% 面积被误判为果园。因此在推理后增加三道后处理：

```
概率栅格 prob (0-1)
    ↓
① NDVI 校验: summer_ndvi < 0.45 → 强制判非果园 (果树常绿 vs 大春已收获)
    ↓
② 二值化 + 连通域去噪: binary_opening 去孤立点 → label 连通域 → 移除 < 0.3 ha
    ↓
③ 置信度分级: prob ≥ 0.7 高置信 / 0.5~0.7 低置信(不确定)
    ↓
矢量化 SHP (字段: area_ha / max_prob / mean_prob / ndvi_summer / conf_flag / prdct_lbl)
    ↓
裁切安居区 (安居区.shp)
```

**后处理结果**：

| 范围 | 处理前 | 处理后 |
|------|--------|--------|
| 安居区 | 59,299 ha（3,520 斑块） | **4,985 ha（1,361 斑块，占比 4%，相对合理）** |
| 全遂宁 | 304,705 ha | 288,133 ha（50,022 斑块，占比 54%，仍过激） |

> 后处理能压掉安居区 92% 的误判，但全遂宁仍过激。根因是模型被 DEM 主导（98.6% 斑块"高置信"地错），跨县光谱迁移失效。

### 6.4 DOM 叠合步骤

1. QGIS 中加载 `人保-安居区DOM.img`
2. 加载 `outputs/anju/orchard_anju_dom.shp`（已在 CGCS2000 GK35 坐标系）
3. 设置 SHP 填充为半透明（如红色 50%）即可在 DOM 底图上查看果树预测区域

## 10. 关键技术决策与已知问题

### 10.1 关键技术修复

| 问题 | 根因 | 修复 |
|------|------|------|
| Winter/Spring S2 下载 404 | S3 URL 月日需前导零（`01`→`1` 不匹配） | URL 格式修正 `{month:02d}/{day:02d}` |
| 遂宁 late_autumn 全 NaN | `run_suining_binary.py` 构建 cube 时bug | 重写 `rebuild_suining_cube.py` |
| 波段维度不匹配（16/68） | 遂宁/叙永季节名不同 | `season_map` 波段名对齐 |
| DEM 全零 | 维度反转 | 修正 shape 顺序 |
| AWS DNS 间歇失败 | 境外域名解析不稳定 | 5 次指数退避重试 |

### 10.2 当前局限

1. **跨县光谱可迁移性差**：叙永（山地果园，李子+柑橘）与遂宁（丘陵/平坝）地理分布差异大，模型被 DEM 主导，F1 仅 0.40
2. **推理过激**：v3 判出遂宁近 58% 面积是果园，严重异常，需后处理（NDVI 校验 + 连通域去噪）
3. **10m 分辨率** vs 细碎果园：四川丘陵区果园往往小块分散，10m S2 像素边界有混合效应
4. **负样本不纯**：WorldCover 非 Tree cover 类别包含部分果园，负样本可能混入果树

### 10.3 改进方向

- **后处理（v3.1 已完成）**：NDVI 校验 + 置信度分级 + 连通域去噪，安居区误判压掉 92%（`postprocess_orchard.py`），但全遂宁仍过激
- **本地冷启动（优先推荐）**：在遂宁本地找果树标注样本（哪怕几十个地块），比跨县迁移靠谱
- **引入 Sentinel-1 SAR**：不受云影响，补充果树冠层结构信息
- **更高分辨率影像**：DOM/航片结合，突破 10m 瓶颈
- **特征筛选**：基于特征重要性筛掉 DEM 之外的噪声特征，或降低 DEM 权重
- **调整阈值**：通过 DOM 人工核查典型斑块，校准概率阈值和 NDVI 阈值

## 11. 关键时相补全与 SAR 融合（v4 规划）

### 11.1 文献依据

| 来源 | 结论 |
|------|------|
| 赣南柑橘（农业机械学报 2024） | 5、9、11 月是柑橘识别关键期；S2+时序 SAR 融合 OA 90%、Kappa 0.86 |
| 苹果园（Sustainability 2023） | 4、5、10 月最优时相；RF+纹理 OA 90%、Kappa 0.88 |
| 果园物候（Remote Sens. 2023） | 物候参数优于原始时序；**跨站点迁移精度大幅下降**（印证 v3 失败根因） |

### 11.2 时相补全方案

当前 4 季（12/1/3/8 月）缺关键期，规划补全为 6-7 期：

| 时相 | 日期 | 云量 | 状态 |
|------|------|------|------|
| late_autumn | 2024-12-11 | 9.5% | 已有 |
| winter | 2025-01-20 | 1.2% | 已有 |
| spring | 2025-03-26 | 0.0% | 已有 |
| **late_spring** | **2025-05-20** | **1.4%** | **待补（本地已有 4 波段，缺 6 个 20m 波段）** |
| summer | 2025-08-28 | 21.8% | 已有 |
| **early_autumn** | **2025-09-24** | **29.9%** | **待下载完整 10 波段** |
| ~~11月~~ | ~~2024-11~~ | ~~86.4%（最优）~~ | **不可用（四川盆地整月 100% 云）** |

> **11 月 S2 全云不可用**，但 S1 SAR 不受云影响，可补 11 月 SAR 特征弥补。

### 11.3 SAR 融合方案

| 项 | 配置 |
|----|------|
| 数据源 | Sentinel-1 GRD VV/VH（后向散射系数 σ⁰，单位 dB） |
| 关键时相 | 5、9、11 月（SAR 不受云影响，11 月可补） |
| 处理流程 | 辐射定标 → dB 转换 → 重投影到 S2 10m 网格 → 时序堆叠 |
| 特征维度 | 每期 VV/VH（2 波段）× 3 期 = 6 波段 |
| 代码模块 | `sar_backscatter.py`（新建），在 `rebuild_suining_cube.py` 中调用追加到 feature cube |

> 现有 `extract_sar_features.py` 直接使用 S1 原始 DN 值提取 zonal mean，**未做后向散射系数 dB 转换**。v4 需新建 `sar_backscatter.py` 补上辐射定标 + dB 转换，并改为逐像素处理（而非 zonal mean）以加入 feature cube。

### 11.4 v4 实际执行结果（2026-08-13）

| 项 | 规划 | 实际 |
|----|------|------|
| 5月 S2（late_spring） | 5/20 | 叙永用 5/12（云 1.3%），遂宁用 5/20（已有缓存） |
| SAR 时相 | 5/9/11 月 | 实际 9月 + 11-12月（5月 SAR 未补，遂宁仅 9/29、11/21） |
| 特征维度 | 6-7 期 | 5 季 S2 + 2 期 SAR = **88 波段** |

**结果**：

| 指标 | v3 | v4 |
|------|----|----|
| CV F1 | 0.40 | **0.42（+2pt）** |
| 遂宁果树面积 | 304,705 ha | 350,625 ha（199,900 斑块） |

**结论**：

1. F1 提升主要来自 **5月 S2**（`vi_late_spring_ndvi`、`s2_late_spring_B03` 进 TOP10），**SAR 贡献有限**（TOP10 无 SAR 波段）
2. **DEM 仍是主导特征**，且遂宁侧 DEM 全零（`rebuild_suining_cube.py` 的 `DEM_PATH` 误指向 `xuyong_dem/xuyong_dem_10m.tif`），是训练/推理不一致的遗留隐患
3. **v4 裸输出未做后处理**，安居区把大春作物大量误判为果园；需套用 v3.1 后处理（NDVI 校验 + 连通域去噪）或补遂宁 DEM 治本

### 11.5 v4 待办（方案已定：去 DEM + 套后处理）

- [ ] **去 DEM 特征**：从训练/推理两侧 feature cube 中移除 DEM（elevation + slope），逼模型学光谱/物候（DEM 是地形偏置导致的伪相关，不可跨区迁移）
- [ ] **套后处理**：对 v4 输出套用 `postprocess_orchard.py`（NDVI 校验 + 连通域去噪），消除大春作物误判
- [ ] 视效果决定是否保留 SAR 波段（当前贡献有限）
